# 模块边界与运行时结构

## 依赖方向

模块之间通过明确接口协作。禁止底层反向依赖应用服务、数据库和路由；依赖注入集中在装配边界，不在工具内部查询全局服务。

| 模块 | 负责 | 边界 |
| --- | --- | --- |
| `api/` | HTTP/WebSocket、参数验证、响应转换 | 调用服务，框架对象不传入业务层 |
| `composition.py` | 装配应用服务实例 | 路由与定时任务共享同一终端服务和 Agent 运行时；服务不反向导入装配入口 |
| `services/` | 用例编排、权限与审计适配、配置和持久化协调 | 可使用 Core 和数据库，不导入 API 或 Web 框架 |
| `core/loop/` | Agent 执行、状态机、事件和审批 | 通过存储接口持久化，通过工具接口调用能力 |
| `core/tool/` | 工具契约、参数与执行规则 | 通过 `ports.py` 注入资产目录、技能加载、命令策略和审计；不查询数据库或定位服务 |
| `core/connectors/` | PTY、SSH、网络和串口协议 | 只接收已解析的连接配置；数据库查询、凭据解密与驱动选择放在 `services/connector_factory.py` |
| `core/llm/` | 模型协议、流式响应和工具调用数据 | 不依赖运行时、提示词组装或资产连接器 |
| `core/prompts/` | 指令文本与格式化 | 不调用运行时、连接器或模型 |
| `db/` | 数据模型和仓储实现 | 不导入服务、路由或装配入口 |
| `shared/`、`utils/` | 基础配置、类型、密钥和通用工具 | 不依赖 Core、业务服务或数据库 |

工具资产目录返回不含连接凭据的 `AssetSummary`。命令策略仍强制人工审批；审计写入失败时不启动命令执行，并释放终端占用。插件命令复用同一个命令处理器，MCP 工具通过绑定到各自服务和工具的回调调用。

终端服务只接收 `TerminalChannel` 接口；`api/terminal_channel.py` 将 WebSocket 及断连异常转换为该接口。鉴权服务接收请求头映射，不接收 HTTP 请求对象。终端缓冲发送失败也会完成连接解绑。

前端允许组件调用 Hook，Hook 调用 API 和共享工具；`hooks/` 不导入组件，`api/` 不导入 Hook 或组件，`utils/` 和 `types/` 不导入这些上层目录。终端文本处理放在共享工具中，不由会话组件提供。

现有运行时回归脚本通过 AST 检查后端依赖，包括函数内导入、相对导入和字符串形式的动态导入；前端 ESLint 通过受限导入规则检查反向依赖。两项检查均由现有 Quality 流程执行。

## 提示词归属

`src/app/core/prompts/` 只维护模型指令和格式化函数，不读取数据库、不调用模型、不执行工具。

| 文件 | 职责 |
| --- | --- |
| `context.py` | 提示词需要的只读输入接口，不引用运行时实现 |
| `defaults.py` | 可配置业务提示词的默认值及设置页约束说明 |
| `agent.py` | Agent 主指令、资产和任务上下文、技能指令 |
| `auxiliary.py` | 会话标题、知识提取的输出契约 |
| `memory.py` | 检索结果说明、记忆不可用回退及不可覆盖约束 |
| `device.py` | 网络设备执行规则 |
| `feedback.py` | 工具取消、缺少说明、等待审批等反馈指令 |

工具名称、参数 Schema 和工具说明仍与 `core/tool/` 中的工具实现一起维护。实际授权、审批、取消、资产范围检查由代码强制执行，提示词不能代替这些检查。

`PromptSettingsService` 负责覆盖值的读取、校验、修订和审计。设置字段保持不变，不迁移或覆盖用户现有设置。不要在业务服务中另写一套默认指令。

## 请求组装

`core/loop/request_builder.py` 是 Agent 消息组装入口：主系统指令 → 已选技能 → 历史 → 当前知识上下文 → 用户请求。动态加载技能也通过该构建器加入一次。

每轮根据当前授权和任务状态重新生成主系统指令。知识上下文保持 `volatile` 缓存标记；压缩历史时不截断系统指令、技能内容或不可覆盖规则。知识条目在格式化前限长，规则放在条目之后完整保留。

构建器的 DEBUG 日志记录消息顺序、角色、缓存分段、字符数和工具数量，不记录提示词正文、密码或授权令牌。历史上下文整理仍由 `ContextManager` 负责；运行中消息裁剪由请求构建器负责，两者作用于不同阶段。

## 运行时与存储

- `core/loop/`：当前唯一的 Agent 会话运行时，负责循环、状态机、SSE 事件、审批与恢复。
- `core/runtime/control.py`：进程级预算、取消和指标控制，不是第二套会话运行时。
- `core/loop/runtime_store.py`：运行时依赖的存储接口。
- `db/repositories/runtime.py`：SQLite 快照、事件、租约与恢复的具体实现。
- `services/console_app_service.py`：组合工具和运行时，注入存储实现及实例身份。
- `services/conversation_factory.py`：API 和后台服务共享的会话服务构造入口，业务服务无需从会话路由反向导入。

旧的会话运行时、事件类型和按风险级别判断审批的未使用实现已删除。现有持久化表、SSE 字段、审批令牌和恢复行为保持兼容。

## 模型调用

当前唯一可调用的后端是 CC Switch 的 Messages 路由，`anthropic` 表示所用协议。连接默认值集中在 `core/llm/cc_switch.py`，具体协议实现位于 `core/llm/providers/anthropic.py`。

Agent、标题生成和知识提取读取数据库中当前默认模型。没有默认记录时使用本地设置或环境配置；显式传入设置文件的离线工具保持隔离。连接地址、模型和密钥不应在辅助生成代码中另行配置。

旧提供商枚举仅用于读取历史记录和凭据迁移，不代表支持继续调用；模型配置写入接口及工厂拒绝其他提供商。旧凭据可迁移为加密记录，但不自动设为默认模型。

Messages 路由没有原生 embedding 接口，知识检索使用现有关键词路径，不再请求其他供应商。模型发现接口返回已配置模型或默认模型，不伪装成远端模型列表查询。

## 验证

在现有 `scripts/eval_agent_dialogue.py` 和 `scripts/eval_runtime_events.py` 中运行回归。重点覆盖指令完整性、动态授权更新、技能不重复、默认模型一致、审批和资产隔离、流式事件及持久化恢复。Python 类型检查使用 `pyright`；接口相关改动还需检查前端构建与实际运行态。

开发后端镜像通过 `requirements.lock` 和哈希校验安装依赖，与 CI 和隔离验收环境保持一致。删除提供商时同步更新依赖清单及锁文件，不能只隐藏前端选项。
